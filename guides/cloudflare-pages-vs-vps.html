2. 什么场景直接用 Cloudflare，别花冤枉钱买 VPS？

  • 个人主页、作品集、产品落地页：纯前端 HTML/CSS/JS 或 React/Vue 构建产物，放在 Pages 上几乎零成本且全球 CDN 加速。
  • 技术博客与文档站：Hugo、Astro、Hexo、VitePress 生成静态页后部署，天然不怕 WordPress 插件漏洞和 MySQL 崩溃。
  • 轻量级信息聚合与定时线索站：就像你现在看到的「小天 VPS 雷达」——静态页面 + Workers Cron 定时采集 + KV 缓存，全链路跑在免费额度内，连一台小鸡都不用额外买。
提醒：免费托管并非绝对无限制，请随时留意 Cloudflare 官方关于 Workers 每日请求数、CPU 时间、KV 读写次数和合规内容政策的条款更新。

3. 什么场景必须老老实实买一台 VPS？

  1. 需要常驻进程或长耗时任务：比如 24 小时运行的 AI Agent 调度中心、Telegram/飞书机器人、定时浏览器自动化、持续监听队列的服务。
  2. 重度依赖 Docker 与传统数据库：想一键 docker compose up 部署开源项目（n8n、Uptime Kuma、私有网盘、SQLite/PostgreSQL/Redis），VPS 自由度高得多。
  3. 需要固定公网 IP 或完整 Linux 环境：对接需要固定白名单 IP 的第三方接口、远程开发、编译打包或自定义网络工具。

4. 个人开发者最稳的“混合架构”

其实两者不是非此即彼，把它们拆开分工反而是性价比最高、最安全的做法：

  • 公开展示层 → Cloudflare Pages / Workers：承载个人主页、博客、VPS 优惠雷达等面向搜索引擎和公开访客的站点，免费抗流量、零服务器被扫端口风险。
  • 私有计算与调度层 → 1 台高性价比 VPS：专门运行 AI Agent 调度、数据库与自动化任务，并通过 Cloudflare Tunnel + Zero Trust Access 藏在后面，甚至可以关掉大部分公网暴露端口。

这样就算你的公开博客突然爆了流量，也完全影响不到后端 VPS 上正在跑的核心服务。
